# الدليل الملكي — تشغيل البوت 24/7 مجاناً عبر bot-hosting.net

المنصة: **https://bot-hosting.net** — خطة مجانية دائمة: **بدون سِبَنِين (no sleep)**، قرص ثابت دائم،
إعادة تشغيل تلقائية عند أي انهيار، وربط مباشر بمستودع GitHub الخاص بك.
المصدر الرسمي للأدلة: `bot-hosting.net/docs` (فحصت الجلسة: 2026-11-22).

## حدود الخطة المجانية (مهم أن تعرفها)

| البند | القيمة |
|---|---|
| الذاكرة | 256 MB (كافية تماماً لبوت تيليجرام polling) |
| المعالج | 25% من نواة |
| القرص | 512 MB دائم |
| عدد البوتات | 1 (سيرفر مجاني واحد لكل حساب) |
| العمل | 24/7 فعلياً — لا وضع نوم |
| **التجديد** | **زر تجديد يدوي كل 4 أيام** (تفاصيل بالأسفل — إلزامي) |
| النسخ الاحتياطي | تلقائي كل ساعة (سجل 24 ساعة) |
| الـ Uptime المستهدف | 99% |

> لماذا Supabase إذن؟ لأن قاعدة بياناتك الحقيقية تعيش على Supabase خارج السيرفر —
> حتى لو حُذف سيرفر bot-hosting لتأخر التجديد، بيانات المستخدمين والاشتراكات والإشارات **محفوظة لا تُمس**.
> إعادة التشغيل بعد أي مشكلة = كلون جديد يقرأ نفس القاعدة في ثوانٍ.

## الخطوة 1 — إنشاء الحساب

1. افتح: `https://bot-hosting.net/login`
2. سجّل الدخول بحساب **GitHub** أو **Discord** (البريد الموثوق مطلوب في الحساب).
3. لا يوجد أي بطاقة بنكية أو دفع — مجاني بالكامل.

## الخطوة 2 — إنشاء النشر (Deployment) من مستودع GitHub

1. من المشروع الافتراضي اضغط **New Deployment** (أعلى اليمين).
2. الاسم: `forexyemeni` — النوع: **Application**.
3. **Source**: اختر **GitHub** ← لأن مستودعك **خاص (Private)**:
   اضغط **Connect GitHub** (تفويض OAuth) ← **Choose a repository** ← اختر
   **ForexYemeni/ForexYemeni_Bot** ← اختر الفرع **main**.
4. اترك **«Pull automatically at every restart»** مفعّلاً — كل إعادة تشغيل تسحب آخر commit تلقائياً.
5. **Runtime**: **Python** (اختر أحدث إصدار متاح 3.12 أو أحدث).
6. راجع الموارد ثم **Launch deployment**.

> المنصة تثبّت الاعتماديات تلقائياً من `requirements.txt` عند كل تشغيل —
> لا تحتاج أي أمر تثبيت يدوي.

## الخطوة 3 — متغيرات البيئة (الأسرار تعيش هنا فقط)

من تبويب **Environment** أضف المتغيرات الثلاثة (فعّل **Secret** لكل واحد ليُخفى):

| المتغير | القيمة | من أين؟ |
|---|---|---|
| `BOT_TOKEN` | توكن البوت من @BotFather | رسالة BotFather عند إنشاء البوت |
| `ADMIN_ID` | رقمك التعريفي في تلغرام | اسأل @userinfobot |
| `DATABASE_URL` | رابط Supabase PostgreSQL الخاص بك | صفحة Supabase → Connect → Session pooler |

مثال شكل DATABASE_URL (قيمك أنت فقط — لا تشاركها مع أحد ولا ترفعها GitHub):

```
postgresql://postgres.<المعرف>:<كلمة_المرور>@aws-1-ap-northeast-1.pooler.supabase.com:5432/postgres
```

> **لماذا pooler وليس الرابط المباشر؟** لأن الـ pooler يدعم IPv4 والاتصالات المتزامنة
> من أي سيرفر استضافة — وهو نفس الرابط الذي اختبرناه ونجح 100%.

## الخطوة 4 — ملف التشغيل

من تبويب **Startup**: تأكد أن **Entry File = `main.py`** (افتراضي المنصة المناسب لمشروعنا).
المنصة تشغّل تلقائياً: `pip install -r requirements.txt` ثم `python main.py`.

## الخطوة 5 — التشغيل والتحقق

1. افتح تبويب **Console** وشاهد الإقلاع: سترى سطور `✅ BOOT: ...` ثم `🚀 Preflight passed`
   — ومن ضمنها: `engine=PostgreSQL (Supabase)`.
2. في تلغرام أرسل **/start** للبوت — تفتح اللوحة الملكية.
3. البوت الآن يعمل **24/7** حتى لو أطفأت جهازك. الانهيارات تعاد تلقائياً.

## الخطوة 6 — التجديد كل 4 أيام (الخطوة الوحيدة المطلوبة منك للأبد)

هذا هو «الثمن» الوحيد للخطة المجانية — **نقرة واحدة كل 4 أيام**:

1. كل 4 أيام: افتح **Billing** ← الزر الأخضر **Renew free plan**.
   (الزر يظهر قبل الموعد بثلاثة أيام، والمنصة تنبهك)
2. حل تحقق الإنسان (captcha) ← **Renew for 4 days**.
3. إن نسيت: لديك مهلة سماح 3 أيام إضافية (~7 أيام كاملة) ثم يُحذف السيرفر
   (تُحفظ نسخة احتياطية يوماً واحداً). بياناتك الحقيقية في Supabase لا تتأثر إطلاقاً.

| الطريقة | ما تفعله أنت | ملاحظات |

| **زر Restart في اللوحة** | لا شيء — نقرة واحدة | الإقلاع يفحص GitHub Releases ويُحدّث ذاتياً قبل تشغيل البوت (`BOOT: UPDATE ✓`) |


## النسخ الاحتياطي (طبقتان)

- **طبقة Supabase**: قاعدة البيانات الحقيقية على سيرفرات Supabase (خارج الاستضافة نهائياً).
- **طبقة البوت**: أرسل `/backup` للبوت ← تصلك لقطة JSON كاملة لكل الجداول في تلغرام،
  ونسخة تلقائية يومية 3 فجراً في مجلد backups.
- **الاسترجاع**: من لوحة الإدارة (النسخ الاحتياطي/الاستعادة) — يرفع JSON ويعيد بناء كل الجداول.

## استكشاف الأخطاء

| المشكلة | السبب والحل |
|---|---|
| البوت لا يرد بعد الإقلاع | Console: إن ظهر `⛔ BOOT: BOT_TOKEN missing` راجع تبويب Environment |
| `database integrity failed` | DATABASE_URL خاطئ أو Supabase متوقف مؤقتاً — تحقق من الرابط وحالة Supabase |
| `password authentication failed` | كلمة مرور Supabase غُيّرت — حدّث DATABASE_URL في Environment |
| الطلب المرفوض `451/403` من مصادر الأسعار | طبيعي أحياناً مع مزودين — البوت يتنقل تلقائياً للمصدر التالي |
| السيرفر حُذف | أعد الخطوة 2 كاملة (المستودع والبيانات سليمان) — ثم اجعل التجديد أولوية |
| بطء الاستجابة | 256 MB و25% CPU كافيان؛ إن زاد الحمل انقل لخطة مدفوعة أو Oracle Cloud (deploy/ORACLE_GUIDE.md) |
