## 2) ما كان يعمل ويجب الحفاظ عليه (محفوظ فعلاً)

- إصلاح الأزرار: `await q.answer()` فوراً + عرض برسائل جديدة + التقاط الأخطاء برد مرئي → **منقول حرفياً** إلى dispatcher.py.
- التحقق الإداري على الخادم في الموجّه وفي صفحات الإدارة → محفوظ ومضاعف (تسجيل admin_probe).
- قاعدة البيانات الأصلية وإعداداتها والتوكن وID المدير → محفوظة دون أي تعديل قيمة.
- تدفقات: الحظر، المدفوعات يدوياً مع الإيصال، التذاكر، النسخ الاحتياطي /backup، منع تكرار الإشارة الآلية.

### أقسام وهمية/شكلية (كانت)
- brokers / accounts / demo / reports / health / security / settings في الإدارة كانت قواميس أوصاف فقط → كلها الآن وظيفية.
- demo كان مجرد «تسجيل متابعة» بلا أسعار ولا P&L → الآن محاكاة كاملة بأسعار حقيقية.

### نواقص وظيفية عولجت
- حصة FREE كانت عرضاً واجهة فقط (عدّ إشارات المنصة لا استهلاك المستخدم) → سجل signal_deliveries + معاملات ذرية.
- لا دورة حياة للإشارة (الإشارة تبقى ACTIVE للأبد) → tracker ببيانات سعر حقيقية + EXPIRED.
- لا تذكيرات انتهاء ولا انتهاء تلقائي فعلي → subscriptions_loop + أعلام remind_3d/remind_1d.
- Broadcast فوري بلا معاينة/تأكيد/إيقاف/عدادات/معدل إرسال → worker كامل مع حدود Telegram.
- الدعم بلا موضوع/نوع/محادثة/رد/إغلاق → tickets + ticket_messages كاملة.
- لا وسائل دفع، لا بحث مستخدمين، لا تقارير SQL، لا صحة نظام، لا أمان مركزي → أضيفت كلها.
- الاستراتيجيات أسماء بلا منطق ودرجة ثقة شبه ثابتة (80+5+5) → 3 استراتيجيات موثقة بأوزان قابلة للقياس + درجات تحقق مسجلة JSON.

### ملاحظات أداء
- اتصال SQLite جديد لكل عملية (مقبول مع WAL) — أبُقي عليه مع busy_timeout + synchronous=NORMAL + فهارس 16.
- حلقة المحرك كانت تنام 60s دنيا مع تداخل عمليات — أصبحت معزولة الأخطاء مع فاصل قابل للضبط.
